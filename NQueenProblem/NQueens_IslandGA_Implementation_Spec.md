## 1. 目的・対象範囲

**[確定]** C言語でNクイーン問題を解く遺伝的アルゴリズム（GA）を実装する。集団を複数の島に分割する**島モデル（Island Model / Migration Model）**を使用し、親選択・交叉・移民等の方式を差し替えて性能を比較する。

設計目的は次のとおり。

1. `fitnessScore == 0` を満たすNクイーン配置を探索する。
2. 島間の移民トポロジー、移民選択、移民先置換、親選択、交叉の方式を変更・比較できるようにする。
3. 可変パラメータを中央集約し、戦略を関数ポインタでモジュール化する。
4. 評価処理の重複、不要な個体コピー、メモリアクセス、繰り返し動的メモリ確保を抑制する。
5. 乱数シードと実験設定を保存し、結果を再現可能にする。

本書は**解を1つ見つける最適化型GA**を対象とし、全解列挙は必須としない。

## 2. Nクイーン問題の定義

$N \times N$ の盤面に$N$個のクイーンを配置し、同じ行・列・斜め方向に2個以上のクイーンが存在しない配置を求める。

クイーン$i$の位置を$(r_i,c_i)$とすると、任意の$i\ne j$に対し：

$$
r_i\ne r_j,\qquad c_i\ne c_j,\qquad |r_i-r_j|\ne |c_i-c_j|
$$

### 2.1 遺伝子表現 **[確定]**

長さ$N$の一次元整数配列を使用する。

$$
X=[x_0,x_1,\ldots,x_{N-1}],\qquad x_i\in\{0,1,\ldots,N-1\}
$$

- 添字$i$は**行番号**。
- `genes[i]`（$x_i$）はその行のクイーンの**列番号**。
- どの行にもクイーンが必ず1個あるため、行の重複は構造的に存在しない。
- **列番号の重複を許容**する。順列制約は設けない。
- 列の変更は `genes[i] = newColumn` で表現する。
- 候補配置数は$N^N$。すべての正解を表現できる。

例（$N=4$）：`[0, 2, 2, 3]` は合法な**遺伝子表現**だが、Nクイーンの制約を満たす解ではない。

### 2.2 適応度（コスト） **[確定]**

適応度は**攻撃制約に違反しているクイーンの組数（衝突ペア数）**とする。小さいほど良く、`fitnessScore == 0` で解と判定する。

$$
F(X)=\sum_{i=0}^{N-1}\sum_{j=i+1}^{N-1}
\mathbf{1}\left[x_i=x_j\ \lor\ |x_i-x_j|=|i-j|\right]
$$

- 同一列に$k$個並ぶ場合、その列の衝突組数は$\binom{k}{2}=k(k-1)/2$。
- 同じペアを二重に数えない。
- 駒による遮蔽は考慮しない（標準的なNクイーンの制約モデル）。
- `queenConflicts[i]` は、行$i$のクイーンが衝突する**相手のクイーン数**。長さ$N$。

$$
F(X)=\frac12\sum_{i=0}^{N-1}\mathrm{queenConflicts}[i]
$$

## 3. 衝突評価と計算量

### 3.1 占有数による$O(N)$評価 **[確定]**

ペア全探索$O(N^2)$ではなく、列と2方向の対角線の占有数を利用する。

- `columnCount[N]`
- `diagDownCount[2*N - 1]`：対角線インデックス `i - genes[i] + (N - 1)`
- `diagUpCount[2*N - 1]`：対角線インデックス `i + genes[i]`

**評価手順**：

1. 3つの占有数配列をゼロクリアする。
2. 全遺伝子を1回走査し、対応する列・対角線の占有数を増やす。
3. 再度全遺伝子を走査し、下式で `queenConflicts[i]` を埋め、合計値の半分を `fitnessScore` に保存する。

$$
\mathrm{queenConflicts}[i]
=(\mathrm{columnCount}[x_i]-1)
+(\mathrm{diagDownCount}[i-x_i+N-1]-1)
+(\mathrm{diagUpCount}[i+x_i]-1)
$$

時間計算量は初期化込み$O(N)$、作業領域は$O(N)$。

**注意**：占有数から全衝突ペアの**件数**は線形時間で計算できるが、衝突ペアを全件**列挙**する場合は出力数に応じた追加コストが発生する。衝突フラグは `queenConflicts[i] > 0` から導出できるため、原則として別配列を持たない。

### 3.2 評価結果の再利用 **[確定：方針]**

- `Individual` に `fitnessScore` と `queenConflicts[N]` を保持し、交叉・突然変異の候補選択に使う。
- 遺伝子未変更個体の再評価は省略する。
- 遺伝子変更後は評価キャッシュを無効にし、使用前に更新する。
- 占有数配列は個体ごとに恒久保存せず、原則として島またはスレッド単位の作業領域を再利用する。**[暫定]**
- 差分更新（クイーン1個の変更時、衝突ペア数を占有数から$O(1)$更新可能）は最適化候補だが、`queenConflicts` 全要素の整合性まで含めた初期実装は**完全な$O(N)$再評価**を優先する。**[暫定]**

## 4. データ構造・設定管理

### 4.1 基本構造体 **[確定：必要情報／暫定：具体型]**

```c
typedef struct {
    int *genes;              // 長さ N
    int *queenConflicts;     // 長さ N
    int fitnessScore;        // 衝突ペア数（0が解）
    bool evaluationValid;    // 評価情報が現在の遺伝子と一致するか
} Individual;

typedef struct {
    Individual *individuals; // islandPopulation 個
    // 必要なら、島内最良の値/添字/別途コピーを保持
} Island;

typedef struct {
    Island *islands;         // islandCount 島
    int generationIndex;
} Generation;
```

`evaluationValid` は計算結果の二重利用や古い衝突情報の誤使用を防ぐための**実装用提案**。`bool` には `<stdbool.h>` が必要。

## 5. 初期集団生成 **[確定]**

- **完全ランダム生成のみ**を採用する。
- 各島の全個体について、各 `genes[i]` に `0`〜`N-1` を一様ランダムに設定する。
- 列の重複を禁止する修正は行わない。
- 生成後、`fitnessScore` と `queenConflicts[]` を評価する。
- 乱数シードは保存し、島ごとに独立した乱数状態を持たせる。**[暫定：実装方針]**

生成・初回評価とも1個体あたり$O(N)$。

## 6. 親選択 **[確定]**

以下の3方式をすべて実装し、設定により切り替えて比較する。

| 方式 | 仕様 |
|---|---|
| Tournament Selection | 無作為に$k$個体を抽出し、`fitnessScore` 最小を選択 |
| Roulette Wheel Selection | `fitnessScore` を非負の選択重みに変換し、重みに比例して選択 |
| Rank Selection | 適応度の順位に応じた重みで選択 |

- **同じ個体が複数回親として選ばれてよい。**
- **エリート個体も親選択の対象に含める。**
- 同一ペアで同じ個体を2回選ぶことの可否は**未確定**。暫定既定値は許可とする。ただし同一親同士では交叉しても遺伝子に差が出ないため、回避オプションを設けて実験可能にする。**[暫定]**

### 6.1 ルーレットの重み **[暫定]**

最小化問題であるため、`fitnessScore` を直接確率として使用しない。初期実装では次を使用する。

$$
w_i=\frac{1}{1+F_i},\qquad p_i=\frac{w_i}{\sum_j w_j}
$$

同一世代の親選択で、累積重みを繰り返し計算しないようキャッシュする。ランク選択も順位を必要なタイミングで準備する。重みや順位は**世代の評価値が変わったときだけ**再構築する。

## 7. 交叉 **[確定]**

1組の親ペアについて、確率 `crossoverRate` で交叉を**実施**する。実施しない場合は親の遺伝子を子にコピーする。その後、突然変異判定を行う。

`crossoverRate` は**「次世代個体の厳密な割合」ではなく「親ペアごとの交叉実行確率」**と定義する。

### 7.1 n点交叉（n-point crossover）

- `crossoverPoints = n` とする。
- 隣接遺伝子間の$N-1$箇所から重複しない$n$個の交叉点を選択する。
- 交叉点で区切られた領域を親A/Bから交互に継承し、通常2個の子を生成する。
- `n=1`なら1点交叉、`n=2`なら2点交叉。
- 交叉点数はパラメータで変更し、**1つの汎用関数**で扱う。
- 候補の列重複は許容されるため、順列修復は不要。
- 本体の遺伝子コピーは$O(N)$。交叉点の一意抽出・整列のコストは実装による。

### 7.2 衝突情報利用型「XOR交叉」

**[確定]** 独自の交叉方式として**XOR交叉**を実装する。ここでの「XOR」はプロジェクト内の便宜的名称であり、ビット単位の排他的論理和を意味しない。

- 2個の親の `queenConflicts[i]` を参照して交叉候補を選ぶ。
- **親A/Bで列番号が異なる位置** `a[i] != b[i]` のみ、実際に遺伝子を変える交換候補とする。
- 交換候補に対して確率判定を行い、選択位置でA/Bの値を子同士に交互継承する。
- 以下2方式を実装・比較する。
  1. **固定確率型**：候補ごとに `xorSwapRate` の確率で交換。
  2. **衝突数比例型**：クイーンの衝突数が多い位置ほど交換されやすい確率を割り当てる。
- `xorForceSwap = true` を既定とする。交叉実行が決まっていて、交換可能な位置があるのに確率判定で選択数0となった場合、**最低1か所**を強制的に交換する。
- 交換可能な位置がなければ無変更を許容する。

**未確定事項を補う暫定規約**：

1. 交換候補は `a[i] != b[i] && (conflictsA[i] > 0 || conflictsB[i] > 0)` と定義する（**OR方式**）。
2. 衝突数比例型では `score_i = conflictsA[i] + conflictsB[i]` とし、`maxScore > 0` のとき `p_i = xorSwapRate * score_i / maxScore` とする。
3. 強制交換時は交換候補から一様ランダムに1か所を選ぶ。
4. `xorSwapRate` は基本確率であり、強制交換を有効にすると実際の交換率はこれと一致しないことをログ上明確にする。

上記は**最終決定ではなく実装可能な既定仕様**。OR/AND/片側優先や衝突重みの計算法はオペレータ内部の設定として変更可能にすることを推奨する。

**注意**：衝突している行を交換すれば必ず改善するわけではない。交叉後は子の評価が必要。`XOR`は通常のn点交叉とは別オペレータとして保持する。

## 8. 突然変異 **[確定]**

**Conflict-guided Random Resetting（衝突誘導型の列番号ランダム変更）**のみを採用する。

1. 子個体の評価情報が最新であることを確認する。
2. `fitnessScore > 0` の子を突然変異の候補とする。
3. `mutationRate` の確率で突然変異を実施する。
4. `queenConflicts[i] > 0` の行を**一様ランダム**に1つ選ぶ。
5. 選んだ行の列番号を、**現在値とは異なる** `0..N-1` の列番号にランダム変更する。
6. `fitnessScore` と `queenConflicts[]` を再計算する。

- 1回の突然変異で原則1遺伝子を変更する。
- 別の行との列番号交換（Swap Mutation）は採用しない。
- 衝突0の個体には突然変異を適用しない。
- $N=1$ は別の列番号が存在しないため変更しない。
- 子の衝突情報がまだ計算されていなければ、**突然変異前に評価する必要がある**。再評価の総回数は交叉・突然変異処理と合わせて最適化する。

## 9. 世代交代・エリート保存

### 9.1 標準の世代交代 **[確定：最新決定]**

**エリート保存付き世代交代型GA（Elitist Generational GA）**を基本方式とする。

- 島あたりの集団数を$P$、エリート保存数を$E$とする。
- 現世代の適応度上位$E$個体を次世代へ**そのままコピーして保存**する。
- 残り$P-E$枠は親選択・交叉・突然変異で生成した子個体で埋める。
- 親選択に重複を許可するため、同じ親が複数回使われても構わない。
- エリートも親として選べるが、**エリート保存用コピー自体は交叉・突然変異で変更しない**。
- $P-E$ が奇数なら最後に生成した2個の子から1個だけ採用する。
- 現世代と次世代の**2バッファ**を持ち、世代終了時に集団ポインタを交換して全体のディープコピーを回避する。

1世代に必要な親ペア処理回数は通常、$\lceil(P-E)/2\rceil$。独立した「交叉試行回数」パラメータは**必須ではない**。

### 9.2 以前議論した置換方式との関係

設計過程では「親直接置換型」と「独立置換型（Worst / Random / Tournament）」の比較案もあったが、**その後の最終決定で、エリート以外の全枠を子で埋める標準の世代交代型GAを採用した**。

したがって、初版で**必須実装とするのは§9.1のみ**。以前の2方式を比較オプションとして追加する場合は別モジュールに分離する。これらを標準動作へ混在させない。**[暫定：旧案の取扱い]**

### 9.3 エリート保存と移民

移民元のエリートは**コピーして送信**し、元の個体を削除・移動しない。移民先でも保護エリート枠を守る必要がある場合、受信側の置換候補から保護対象を除く。**[暫定]**

## 10. 島モデルと移民

### 10.1 島の独立進化 **[確定]**

- `islandCount` 個の島を持ち、各島でGAを実行する。
- 島ごとに集団・評価結果・乱数状態を管理する。
- `migrationInterval` 世代ごとに移民イベントを実施する。
- 移民元の個体は保持し、**コピーを他島に送る**。
- 同一移民イベント中の受信処理で更新された個体が、そのまま別島への送信元として混入しないよう、**送信個体を先にスナップショットする**。

### 10.2 移民トポロジー **[確定：3方式を比較]**

1. **Ring**：一方向のリング（島$i$から島$(i+1)\bmod I$へ）。
2. **Fully Connected**：自島を除く他のすべての島が移民先候補。
3. **Random**：移民先をランダムに決定（自島は除外）。

**[暫定]** 公平な比較のため `migrationCount` は**送信元1島が1イベントで送るコピーの総数**とする。Fully Connectedでは、それを送信先に配分する（各相手へ同数を送る方式ではない）。同時に大量の移民を受ける場合、受信側容量制約・競合時の順序を定める。移民の割当は可能な範囲で送信先を均等にし、収容できない割当は再配分する。受け入れ枠が不足する設定は事前検証で拒否するか、イベント処理で明示的に制限する。

### 10.3 移民個体の選択 **[確定：4方式を比較]**

| 方式 | 選択方法 |
|---|---|
| Best | 移民元の高適応度個体から選択（`fitnessScore` 最小） |
| Random | ランダムに選択 |
| Tournament | トーナメントで選択 |
| Diversity-based | 遺伝的な相違度を指標に選択 |

**標準設定はBest。** ユーザーが指定した「エリートをコピーして移民」はこの設定に該当する。その他の3方式は**比較実験用**として残す。

**[暫定]** Diversity-basedの距離はハミング距離とする：

$$
d_H(A,B)=\sum_{i=0}^{N-1}\mathbf{1}[a_i\ne b_i]
$$

移民元候補と移民先の集団間で、平均または最近傍距離を最大化する選択を後で詳細化する。**初期実装では移民先との最近傍距離の最大化**を採用し、比較コストが高いことを明示する。同距離なら適応度が低い（良い）個体を優先し、それも同じなら乱数で決める。**[暫定]**

### 10.4 移民先の置換 **[確定：2方式を比較]**

1. **Worst Replacement**：受信島の適応度の低い（`fitnessScore` が大きい）個体から順に置換する。
2. **Random Replacement**：受信島の置換可能な個体から一様ランダムに置換する。

**標準設定はWorst。** 最新の指定（移民元のエリートをコピーし、移民先の下位個体を丸ごと置換）は **Best + Worst** に該当する。

- 置換は**遺伝子だけでなく、適応度・衝突情報も含む個体単位のディープコピー**で行う。
- 受信先で同じ格納位置を同一移民イベント中に重複置換しない。**[暫定]**
- 原則として移民受入は**無条件**とする。受信側の保護エリートは置換対象外とする。**[暫定]**
- `migrationCount` と `eliteCount` は**別のパラメータ**。移民数がエリート数を超える設定で、Best方式が非エリートまで含めて送るかどうかは、**上位から送る**とする。**[暫定]**

### 10.5 移民設定の公平性 **[要検証]**

トポロジー間比較では、可能な限り送信島ごとの総移民個体数、島数、島内個体数、世代数、乱数条件を揃える。特に完全結合型だけ送信個体数が増えていないか確認する。

## 11. 全体の実行フロー

```text
1. GAConfig を読込み、パラメータを検証
2. 島・世代バッファ・個体・作業配列を確保
3. 島ごとに完全ランダム初期集団を生成して評価
4. 初期集団内に fitnessScore == 0 があれば成功終了
5. 世代ループ（maxGenerations まで）
   5.1 各島でエリート上位 eliteCount を次世代に保存
   5.2 残りの枠が埋まるまで親2個体を選択
       - crossoverRate により n点/XOR 交叉を実行、または親をコピー
       - 子を評価して queenConflicts を得る
       - mutationRate により衝突誘導型突然変異
       - 変更後の子を評価し、次世代に格納
   5.3 各島の世代バッファを交換
   5.4 移民間隔に到達した場合
       - 全島の送信者を選択し、コピーを一時保存
       - トポロジーに従い送信先を割当
       - 受信先のWorst/Random対象を置換
       - 必要なら島内エリート情報を更新
   5.5 解の存在を検査。fitnessScore == 0 なら成功終了
   5.6 ログ・統計を書き出す
6. 最大世代数到達時は未発見終了
7. 全資源を解放
```

**[暫定]** 移民実行のタイミングは「新世代完成後・終了確認前」とする。正解をできるだけ早く検出したい場合には子生成直後にも早期終了を確認してよいが、評価回数・測定条件を統一して比較する。

## 12. 性能最適化方針

### 12.1 計算量

| 処理 | 標準的な目標 |
|---|---|
| 初期個体生成 | $O(N)$／個体 |
| 個体の適応度・各クイーン衝突数評価 | $O(N)$／個体 |
| n点交叉／XOR交叉の遺伝子組み立て | $O(N)$／親ペア（交叉点準備は別） |
| 衝突クイーンを1個ランダム選出 | $O(N)$走査（候補配列作成時） |
| 子の変更後の評価 | $O(N)$／個体 |
| 1世代の全子生成 | おおむね$O((P-E)N)$／島＋選択・ソート・移民のコスト |

上記は**最悪／漸近オーダー**の目安であり、実測時間は$N$、島数、親選択方式、移民方式、メモリ帯域・キャッシュの影響を受ける。

### 12.2 メモリアクセス・確保

- `genes` と `queenConflicts` は各個体内で連続メモリに格納。
- 個体群の配列も連続確保する。
- **ポインタの受け渡しは不要なコピーの削減に有効**だが、分散した小メモリ確保やポインタ追跡がキャッシュ効率を悪化させ得る点に注意する。
- 配列確保・解放を世代ループ内で繰り返さず、固定の作業領域を再利用する。
- 世代更新は現／次世代バッファの切替で実施する。
- 適応度未変更のエリートや移民コピーの再評価を省略する。
- XOR交叉は既存の `queenConflicts` を読み、独立した$O(N^2)$衝突判定を行わない。
- 並列化する場合は島単位の独立した乱数状態と作業領域を使用し、グローバル `rand()` を並列実行から使用しない。

### 12.3 優先度

1. 計算結果の正しさ（評価キャッシュの整合性）。
2. 余分な$O(N^2)$処理の排除。
3. 不要な再評価と割当・解放の削減。
4. 連続メモリ化とコピー削減。
5. 必要に応じ、差分評価・島単位並列化・追加の低レベル最適化を検証する。

## 14. 終了条件・ログ・評価実験

### 14.1 終了条件 **[確定]**

- いずれかの島で `fitnessScore == 0` の個体を発見：成功終了。
- `maxGenerations` に到達：未発見終了。
- 不正パラメータ、メモリ確保失敗：エラー終了。

### 14.2 ログ **[暫定]**

毎回の実験で最低限、次を保存する。

- 実験ID・乱数シード・日時・各方式名・全パラメータ
- 世代番号と各島の最良・平均 `fitnessScore`
- 全体最良 `fitnessScore` と解発見世代
- 実行時間（壁時計時間）
- 適応度評価回数／交叉実行回数／実際に遺伝子が変化した子の数
- 突然変異実行回数／移民実行回数・移民個体数
- 失敗時には最終最良個体の配列

CSVを基本形式とし、必要に応じて個別の解・設定情報をテキスト／JSONで保存する。

### 14.3 比較の公平性 **[要検証]**

- 各設定で複数の乱数シードを用いて反復測定する。
- `N`、島数、各島個体数、評価予算（fitness評価回数など）を揃える。
- 成功率、解発見までの評価回数、実行時間、世代数、最終最良適応度を比較する。
- 移民なしをベースラインとして含め、移民の効果を分離する。
- トポロジー差以外は固定して比較し、総移民量を揃える。
- 最適化の優劣は$O$記法のみで結論せず、実測・分散・再現性で評価する。

## 15. テスト要件 **[暫定：実装に必須]**

1. **小規模の正解検証**：$N=1$で解、$N=2,3$で解が存在しないこと、$N=4$で既知の2解を正しく評価できること。
2. **評価関数の照合**：ランダム個体で$O(N)$占有数方式の結果を$O(N^2)$の総当たり参照実装と照合する。
3. **衝突情報整合性**：`sum(queenConflicts) == 2*fitnessScore`。
4. **遺伝子範囲**：初期化・交叉・突然変異・移民後も全遺伝子が`[0,N-1]`内。
5. **XOR交叉**：交換候補が存在する場合、`xorForceSwap=true` で実交換1か所以上。交換候補がない場合は無変更を許可。
6. **エリート**：世代更新で保護個体が保持されること。移民後も意図した保護規約と整合すること。
7. **移民**：元個体のコピーが送られ、移民元を改変しないこと。同一イベントでの移民先枠重複を防げること。
8. **再現性**：同じ設定・同じシードで再現できること（並列実行時はスケジューリング依存を排除する設計が必要）。
9. **メモリ安全性**：ASan/UBSan等でリーク、二重解放、境界外アクセスがないこと。

## 16. 未確定事項と実装時の暫定規約まとめ

| 論点 | 当面の実装規約 | 後から比較・変更可能か |
|---|---|---|
| XOR交叉の候補条件 | 親A/Bの衝突情報のOR、かつ遺伝子値が異なる位置 | 可 |
| XOR衝突比例確率 | `(conflictsA[i]+conflictsB[i]) / maxScore` に基本交換率を乗算 | 可 |
| XORの強制交換 | 候補が存在すれば最低1か所を一様ランダムに強制交換 | 確定・可 |
| ルーレット重み | `1/(1+fitnessScore)` | 可 |
| 移民Diversity指標 | ハミング距離／最近傍距離最大化 | 可 |
| 移民数の単位 | 1送信島・1イベントでの送信総数 | 可 |
| 移民イベントの順番 | 新世代完成後に一斉送信スナップショット→置換 | 可 |

| 世代更新 | エリート保存付き全残余置換（標準） | 以前の定常状態案を拡張として追加可 |

| 突然変異 | 衝突誘導型ランダム列変更のみ | **確定** |
